# 终端机器人接入示例

本示例展示“消息 -> 独立用户会话 -> Provider A -> 终端回答”。不包含微信接收、发送、Android 控制或任何生产机器人配置。

## 无凭据体验

在仓库根目录运行 `node examples/bot-adapter/run.mjs`。默认使用合成回答，没有网络调用。

## 真实问答

先部署 Provider A、接入账号并完成知识库问答验证。仅在示例后端环境配置 `PROVIDER_A_URL` 和 `PROVIDER_A_SERVICE_TOKEN`，然后执行：

```sh
node examples/bot-adapter/run.mjs --real
```

服务凭证对应 Provider A 的 `IMA_QA_INTERNAL_SERVICE_TOKEN`。内部接口只能在可信内网访问，禁止通过公网反向代理暴露。凭证不能进入网页、截图或 Git。

可用 `PROVIDER_A_DEMO_QUESTION` 设置与自己的知识库相关的问题。真实模式发起两位模拟用户的真实问答，回答仅在本机终端显示。

## 目前边界

- 每位用户使用独立的散列身份，同一用户的消息串行并沿用会话。
- 查询 `/internal/provider-a/capacity` 决定同时派发数量，0 容量等待；示例请求最多等待 120 秒。
- 同一用户与消息 ID 在当前进程内不重复派发；失败记录也不自动重发。相同 ID 更换问题被拒绝。
- 示例最多保存 1000 条进程内回执，重启后不保留。生产使用必须先实现持久去重回执和不确定完成态处理，不能把本示例当作生产防重复保证。
- 这是用于学习和二次开发的最小参考适配器，不是可直接接入消息平台的生产机器人。Provider A 服务端的持久幂等、取消及不确定状态恢复已有自动化测试和合成演练覆盖；本示例自己的消息回执仍只保存在进程内。生产适配器必须持久保存平台消息处理状态，并对平台回复做去重。
