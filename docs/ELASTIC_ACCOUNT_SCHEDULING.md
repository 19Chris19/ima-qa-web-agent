# 账号弹性并发（本地候选，默认关闭）

本特性基于稳定提交 `286653e5e08679d7534172c0188831c01310668d`，独立分支
`codex/elastic-account-scheduling-20261019`。纯计数控制器与现有 Provider
账号槽位、任务公平队列结合，不依赖尚未合并的其他协议功能。
本轮不提交 PR、不部署，不修改现有账号库、环境配置、历史或 Air 机器人。

## 已证明的范围

2026-10-19 官方网页：同一登录账号、五个不同的**已有**会话、快速模式
`official_3`。首轮五次点击集中在约 2.8 秒内，3 次成功、2 次显示提问过快；
第二轮约每 3 秒启动一条，5 次均成功，五路正文共同输出约 3.35 秒，刷新恢复均通过。
脱敏时间线见 `test/fixtures/elastic-five-session-observation.json`。

这证明该账号和模式可以同时处理五个独立会话。它没有证明通用频率阈值、
20 路/账号、100 路全局、其他账号/模式、持续吞吐量或 Provider/BFF 端到端效果。
`COMPLETED Code=3` 仍只归类为 temporary；不把所有 Code=3 都断定为频率错误。

## 运行规则

| 项目 | 默认规则 |
| --- | --- |
| 开关 | `IMA_QA_ELASTIC_ENABLED=false`；关闭时保留原静态槽位行为 |
| 冷启动 | 未验收范围为 1；已验收范围使用独立初值；学习不持久化 |
| 本地硬上限 | 每账号最多 20、整个实例最多 100；均可调低，非法配置启动前拒绝 |
| 发起节奏 | 每账号至少间隔 3 秒；不同账号各自计时 |
| 增长 | 有等待需求、饱和请求成功至少 10 次、距上次调整至少 60 秒，最多加 1，且不超过该账号/模式的已验收上限 |
| 限流/配额 | 当前窗口减半，最低 1；发起间隔加倍，最多 30 秒；暂停新发起 15 秒，重复时指数增加至 120 秒 |
| 其他上游错误 | 同样减窗退避，标记 upstream_error；保留既有连续错误冷却逻辑 |
| 登录失败 | 明确鉴权错误仍隔离账号；频率/配额错误不会变成登录失效 |
| 旧请求完成 | 通过运行代际检查；退避前启动的成功请求不能清除退避或触发增窗 |
| 正在回答 | 降额后继续执行，等自然完成；不取消、不自动重问、不切换会话所属账号 |
| 同一会话 | 保留队列串行、账号绑定；池的直接调用也保护已知 sessionId 同时只能执行一次 |
| 等待 | 公平任务队列沿用既有限额；绕过任务队列直接调用的等待最多 64 条、180 秒，可取消 |

只有真实业务请求产生反馈，没有额外探测问答，没有失败自动重试。
发起间隔是账号共享的，不会按应用/访客各发一份额度。
同一账号的不同模式共享总活动数、发起节奏和退避；验收额度按账号、登录主体、模式和实际模型分别匹配，未知范围保持 1。

显式开启弹性后，私有验收记录的初值/上限及 `maxPerAccount` 决定学习窗口，账号库原
`maxConcurrent` 仍保留为静态配置，关闭弹性即可恢复；不会将学习值写回加密账号库。
`pool.accountCapacity(account)` 是实际窗口，管理详情中的 `elastic` 给出当前窗口、
上限、间隔、下次可发起时间和最近调整原因。健康、网页资格及策略容量汇总采用
有效窗口并受全局上限约束。capacity 表示总执行额度，available/schedulable
还受活动请求、发起节奏和资格约束，不能将各策略额度直接相加。

命名应用、策略资格、存储故障保护、不同账号的并行双路合同均继续生效。
账号被移除后清除对应计数；凭证替换清除学习并作废旧反馈。

## 配置

全部变量及默认值见 `.env.provider-a.example` 的 `IMA_QA_ELASTIC_*` 一节。
采用 auto 账号池容量时，Provider 公平队列随有效容量变化；fixed 模式继续作为额外
的全局约束，池本身始终执行 100 的上限。访客请求限流、网站待发队列和网关额度
仍是独立限制，不会为了追求并发而自动放宽。

例如 5 账号 × 20 = 100 是**允许配置的理论上限**。以每账号 3 秒间隔启动，
第 20 条最早约第 57 秒才发起，较早请求可能已完成，因此不能把配置上限当作实际
同时运行数或每秒请求数。

## 内存与资源

每账号只保留几个计数、时间戳和代际，不保存正文、凭据或额外来源副本；按账号数增长。
共享一个发起唤醒计时器，不做轮询。直接等待者各有一个有界超时计时器，取消、
完成、超时及关闭时清理。活动 session 集合最多与执行槽位同量级。
原有任务队列限额不变，没有新的无界后台队列或定时落盘。

首版 e25db3c 的历史轻量对照：静态/弹性各 30 轮、每轮 100 个模拟任务，均 3,000 次；
弹性观察到的增量峰值 RSS 比静态约多 0.44MiB，状态通知次数相同。
这里只测调度器和轻量模拟流，使用虚拟启动时钟，不代表整个 Provider 的内存或吞吐量。
原始脱敏指标见 `docs/reliability/elastic-scheduling-20261019.json`，复现：
`node --expose-gc scripts/benchmark-elastic-scheduling.cjs [--elastic]`。

并发回答自身的内存、带宽、IMA 额度和下游开销仍随负载增加。
100 路模拟槽位正确性不等于生产资源验收，不能用调度器的小计数内存替代整个服务测量。

## 分账号、分模式的验收记录

`IMA_QA_ELASTIC_ACCOUNT_LIMITS_JSON` 为私有 JSON 数组（最多 256 条），每条含：
`accountId`、`principalFingerprint`（账号库原有的 HMAC-SHA256 Base64URL 指纹；也接受 64 位十六进制输入，按原样匹配）、`mode`、`modelId`、`modelType`、
`validatedMaxConcurrent`、可选 `initialConcurrent`。
缺省初值取全局 initialConcurrent 与已验收上限的较小值；找不到准确记录时始终为 1。
显式初值不得超过已验收上限，已验收上限不得超过理论上限。

mode 仅接受当前适配器支持的 classic_knowledge、knowledge_agent、ima_agent、ima_agent_auto。
此处描述当前稳定适配器的固定请求路径，不代表新增了快速/深度/模型选择功能；
未来接入新的思考模式或适配器时，必须扩充验收键与相应测试，不能继承旧额度。
已有官方网页五路观察不能直接变成本 Provider native_bound 模式的验收记录。
本分支只保存合成记录，未为任何生产账号签发新验收额度。

### 显式五路试运行

维护者明确批准后，可用独立的 `IMA_QA_ELASTIC_TRIAL_LIMITS_JSON` 设置临时试运行。
每条仍准确绑定 accountId、principalFingerprint、mode、modelId、modelType，另含
maxConcurrent 和可选 initialConcurrent。试运行硬上限为 5，不能借此开启 20 路。
同一范围不得同时配置正式验收与试运行记录；未匹配范围继续为 1，切换模式、模型
或登录主体不会继承额度。重启只使用明确配置，不进行自动探测或问答。

管理快照以 limitBasis=operator_trial 区分，configuredMaxConcurrent 是配置上限，
validatedMaxConcurrent 仍为 1；它不伪造逐账号、逐模式验收。删除试运行记录即可
回到未验收范围的 1 路，或关闭弹性恢复原静态槽位。账号、凭据和历史不迁移。

## 调用方分配

`IMA_QA_APPLICATION_SCHEDULING_JSON` 支持 enabled、default、applications。
applications 的键必须为服务端鉴权产生的 `application:<id>`，或明确的 legacy 角色
ordinary/internal。旧共享凭据按角色计额，不能宣传为网站/MCP/CLI 各自隔离；
独立分配需要独立命名应用的两类凭据，当前生产凭据不自动更换。
同一命名应用的普通/内部凭据共用额度，客户端传来的应用名或配额字段无效。

每项可设置 maxConcurrent（0–100）、queueLimit（0–4096）、weight（1–20）、
maxWaitMs（1–3600000）。默认 100/30/1/180000；全局队列与账号池继续构成额外约束。
权重只决定多个可执行应用争用空位时的发起顺序，不抢占正在运行的回答。
空闲应用没有保留槽位；其他应用可使用空闲全局额度，仍须遵守自己的硬上限。
同应用内继续按访客轮转，同一会话 FIFO 串行。等待超时终结本次已接收任务，
错误码 queue_wait_timeout；按原接收时间计算，重启不会重置等待预算，不自动创建第二次请求。

容量接口仅增加当前已认证应用的 allocation 视图，包含自身上限/使用/排队/等待预算；
不返回其他应用配置、账号验收表或凭据。新字段只在应用调度显式开启时提供。
知天下通过现有两类凭据检查 applicationId 配对，并使用实际应用上限展示容量。

联合本地验收：知天下分支 codex/elastic-website-admission-20261019，
固定基线 8e1f0016a2940e56674e584e231108cb1e599b8e；两仓的具体提交与制品摘要
在联合交付清单中固定，不自动追随 main。
