# Provider A 部署与真实验收指南

本文说明如何在**隔离部署**中验证 Provider A v0.3.0。自动化测试不会登录 IMA，也不能证明目标共享知识库授权、上游问答质量或真实容量；这些步骤由部署者使用自己获授权的账号完成。

## 安全边界

- 只使用你有权使用、且已加入目标 IMA Web 共享知识库的账号。
- 首次验证请在单独目录、独立 `.env` 和独立 `runtime/` 下运行，使用非生产端口；不要让测试版和生产版共用账号库或密钥。
- 本指南的示例使用 `3122`。确认端口未被占用；不要为测试重启或改写正在运行的生产服务。
- IMA 问答是实际上游调用，可能受上游限流、账号状态和共享库权限影响。先做单账号单问题验收，不要一开始就跑并发演练。
- 不要把管理员 token、账号身份、二维码、回答原文、真实来源摘录或运行日志贴到公开 Issue、截图或 GitHub。

## 获取 v0.3.0

建议从正式版本标签获取代码，确保验收对象与 GitHub Release 一致：

```bash
git clone --single-branch --branch v0.3.0 --depth 1 \
  https://github.com/19Chris19/ima-qa-web-agent.git ima-qa-web-agent-test
cd ima-qa-web-agent-test
npm ci
```

Windows PowerShell 可将克隆命令写成单行。使用 GitHub 网页下载时，请选择 `v0.3.0` 标签对应的源码 ZIP。

## 准备隔离实例

先确认 Node.js `18.18` 或更高版本，以及维护机能够打开 Chrome、Chromium 或 Ego Lite。用目标共享知识库的**数字 ID**初始化，并给测试实例单独分配端口：

```bash
npm run setup:provider-a -- --kb <共享知识库数字ID> --port 3122 --host-port 3122
npm start
```

初始化会在当前克隆目录生成权限受限的 `.env` 和 `runtime/`。不要复制生产环境的 `.env` 或 `runtime/` 到此处。记下本机 `.env` 中生成的 `IMA_QA_ADMIN_TOKEN`，只在本机管理页输入，不要发送给他人。

打开 `http://127.0.0.1:3122/admin.html`，输入管理员 token。桌面扫码模式要求**运行 Node 服务的维护机**能启动可见浏览器；纯 Linux 或 Docker 服务器请按[远程服务器 + 本机扫码](./DEPLOYMENT.md#远程服务器--本机扫码)使用 SSH 隧道和 CLI。

## 单账号端到端验收

建议选择一个知识点明确、你能判断答案是否正确的测试问题。先确认账号已被知识库所有者加入你配置的同一个共享库。只验证一个账号、一个会话，不要用生产账号做破坏性操作。

1. 在管理页点击“接入账号”，先填写账号显示名和“知识库验证问题”。问题应与你自己的共享库相关且可人工判断；默认问题可直接使用，也可改成已知答案的问题。
2. 使用待接入账号扫码并完成手机确认。登录态验证后，受控浏览器会关闭，系统自动对该账号执行一次真实 `knowledge_agent` 问答验证。等待任务显示完成，不要重复点击接入。
3. 通过标准：界面显示“账号已接入，可用于知识库问答”；容量中可调度账号只增加 `1`；探针没有写入普通客户的会话历史。v0.3.0 空白新账号库默认使用 `knowledge_agent` 模式。
4. 如果自动验证失败，账号凭证会保留但不会获得该模式的调度资格。先查看脱敏错误类别和账号详情；修复网络或共享库成员资格后，可在账号行点“验证问答能力”手动重试。重试会再次发送真实问题，不会自动反复调用。
5. 回到主问答页，提出一个与目标共享库直接相关的问题。检查回答是否有用、来源是否存在且确实来自预期知识库。仅有答案文字、但没有可确认的知识库来源，不算通过。
6. 在同一个会话提出追问，确认追问承接前文而不是新开上下文；然后新建另一个会话，确认它不会显示前一个会话的历史或来源。
7. 停止测试进程，再用同一测试目录和私有 `runtime/` 重启。确认账号仍为可用于问答、容量没有重复增加，并再次检查管理页健康状态。

任一步骤失败都保留脱敏错误类别和阶段即可。暂态网络错误、上游限流、登录失效、知识库授权失败要分别记录，不要据此自动刷新或覆盖账号凭证。首次验收失败时，先检查目标账号是否加入正确的共享库、服务端网络和管理页状态，再由维护者决定是否手动重试。

## 多账号与并发验收

只有单账号端到端验收通过、且有至少两个身份独立的授权账号后，再使用管理页“并发演练”。这会向真实 IMA 发送问答：

- 先做基线并发，模拟用户数等于可调度的独立账号数；检查每个模拟用户的首问、追问、来源和隔离结果。
- 再考虑两倍账号数的排队压力测试；确认队列最终清空，并人工检查回答质量和来源。
- 每位客户的问题应针对你的共享库内容。系统不自动给答案质量打分，需维护者人工复核。
- 演练前普通队列必须为空。演练期间普通 `/api/ask` 暂时返回 `503`；不要在有真实用户流量时启动。

如果只有一个账号，跳过并发演练。一个账号的测试结果不能外推为多账号容量或生产并发承诺。

## 代码侧验证

无需 IMA 账号或凭证即可运行代码测试：

```bash
npm ci
npm test
npm pack --dry-run
```

这些检查覆盖 Provider A 的合成/模拟路径、隔离、取消、超时、幂等和发布包内容；它们不是 IMA 登录或真实知识库问答证明。可选的长时合成稳定性检查默认约 30 分钟，完全使用临时合成数据，不会访问 IMA：

```bash
npm run soak:synthetic
```

如果改变合成演练时长或并发，可通过 `SOAK_DURATION_MS` 和 `SOAK_CLIENTS` 环境变量配置。不要把这个合成压测的并发结果当作真实 IMA 账号池容量。

## 验收记录模板

只记录不含个人或知识库敏感信息的结果：

```text
版本标签/提交 SHA：
操作系统与 Node.js 版本：
npm ci / npm test / npm pack：
扫码接入：通过 / 失败（脱敏错误类别）
验证问答能力：通过 / 失败（脱敏错误类别）
目标来源是否出现且相关：是 / 否
同会话追问：通过 / 失败
重启后账号状态与容量：通过 / 失败
并发演练（如适用）：档位、成功/失败数、队列是否清空
```

可以提交上述脱敏摘要作为版本体验反馈。请勿附管理员 token、账号名称或身份、知识库 ID、真实问答内容、来源摘录、二维码、Cookie、refresh token 或 `.env`。
