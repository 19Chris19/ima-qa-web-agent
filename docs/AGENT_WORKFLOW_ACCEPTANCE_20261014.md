# Agent 接入候选：本机验收与剩余边界

本记录针对 PR #23 的 CLI / STDIO MCP / 单入口中文 Skill 候选，基于已发布 Provider v0.6.0。客户端仍是未正式发布的 0.1.0 候选，不因本次测试自动成为稳定 Release。

## 产品流程与独有价值

用户安装 Skill 后，应由 Agent 按同一入口识别“连接已有服务”或“部署自己的 Provider 并人工扫码”。Skill 不能单独提供账号、网络桥或绕过扫码；远程调用方也不应取得管理员凭据。

本候选将这些既有项目经验交付给 Agent：

- 固定知识库范围与原生 knowledge-agent 合同，避免每次在网页探索 @知识库或私有请求结构。
- 明确联网意图和实际联网证据的区别；不把参数成功冒充已联网。
- 同会话追问、稳定 requestKey、丢失响应恢复、长任务观察及显式取消。
- 引用键与显示编号的精确关联、知识库/网页/unknown 依据区分、实际步骤和纯文本推荐问题。
- 完整私有归档与内容草稿交接；资料中的指令不进入 Agent 操作流程。
- 首次部署、人工扫码、权限核验、待资格门禁与问答成功分别验收；不初始化空池覆盖旧安装。

## 本机实际验证

使用正在运行的唯一 Provider 和已有五账号，以新的客户端身份创建专用验收会话。没有启动第二套账号池，没有扫码、改账号、改生产代码、重启服务、切公网或操作 Air 机器人。正常问答会产生新的验收任务/会话记录。

| 项目 | 结果 |
| --- | --- |
| CLI / MCP 安装 | 项目事务安装器完成注册；私有 profile 为 0600 |
| Skill 发现 | Codex app-server 的 skills/list 实际发现唯一 ima-qa，中文名 ima 知识库助手，启用状态正常；没有启动另一个模型 Agent |
| SDK STDIO 握手 | 发现 6 个工具；协议 stdout 无额外日志 |
| 两类凭据 | 普通与内部鉴权接口返回同一命名应用；ready=true |
| 真实首问 | 成功、完整，1493 字符，约 35 秒，9 个引用键，其中 2 个知识库引用键；实际关联 2 个不同网页，3 个过程阶段 |

上述真实测试由当前 Agent 使用 MCP SDK 调用实际注册的工具完成，覆盖协议及内容交接。Skill 发现验证和阅读并应用流程不等于已证明所有模型会自动选择正确流程；首次陌生用户的行为评测仍未完成。

本次真实首问完整结果 JSON 为 42,060 字节，终态 summary 为 3,706 字节。活动 summary 不重复发送正文和巨大来源数组；终态可完整读取或归档。这是工具载荷样本，不是模型 token 使用量的 A/B 结论，也不减少 Provider 接收上游资料所需的传输。

## 尚未验收与运行观察

1. 新电脑从零部署、真实扫码、知识库加入/资格验证的完整流程；本机复用有效登录态不代表这些场景已通过。
2. Windows 真机、Linux 远程维护、跨设备 MCP 配置及不同 Agent 的触发行为。
3. 与原生 IMA 同题的答案质量对照、公开内容逐项原文核验、量化 token 对照测试。
4. 当前生产服务出现过控制接口无响应。只读采样显示当时主线程在 `generation-store` 的同步提交子进程中等待；已有实现的单次超时为 20 秒。这是独立运行风险，原因和修复需要继续调查。本次未改生产代码或重启，不能把恢复响应当成该问题已修复。

当前工具开放固定范围问答、可选联网、追问、任务/会话读取与取消、资料导出。未开放跨库切换、全库遍历、上传、模型切换或 IMA 的其他产物操作。建议先完成首次扫码及跨机验收，再发布独立 agent-v0.1.0；公开安装以实际 Release 状态为准。
