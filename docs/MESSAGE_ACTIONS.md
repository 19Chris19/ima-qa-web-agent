# 消息操作与回答恢复

回答下方的刷新图标用于重试或再问一次，悬停与辅助技术可读取操作名称。手机可长按已发送的问题，或点击其下方的“⋯”；桌面也可右键打开消息操作。菜单提供复制问题与当前可用的恢复操作，支持关闭按钮、遮罩和 Escape，关闭后恢复焦点。已有文字选区优先使用原生菜单；复制不可用时提供可选文字。

- 回答成功：再问一次会在当前会话新增一轮，原回答保留。
- 确认失败或停止：重试前读取原任务身份与终态，保留草稿与联网意图；两个入口共用一次操作锁。
- 结果未知或提交回执不明：只检查或恢复原任务，不能自动重新提交。
- 没有回答时简短提示；部分回答保留并标注未完成。提交明确被拒绝时保留草稿，不冒充已接收的对话轮次。
- 任务仍在进行时，消息菜单仅提供复制；暂停的待发问题仍需单独处理。

不自动重试、不替换历史、不引入回答分支或额外模型调用。没有新增网络请求，除非用户明确操作恢复或重试；无新的依赖。

## 验证

`npm test` 覆盖单次派发、原任务身份检查、草稿和部分内容保留、未知结果恢复、消息菜单、选区与复制回退。`npm run test:mobile-ui` 使用合成任务和 Chromium 原生触摸事件，覆盖长按松手、正常点按、滚动取消、面板关闭与焦点、手机输入栏和来源角标。测试不加载真实账号池或访问 IMA。

iOS Safari 与 Android Chrome 真机的文本选区、系统菜单和软键盘行为仍需人工验收。本变更只提供源码与本地预览，正式部署及真实问答沿用单独确认流程。
