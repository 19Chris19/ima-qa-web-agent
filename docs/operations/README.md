# Provider A 服务管理与独立状态页

本地候选，尚未部署。新版后台继续使用 Provider 原有管理 API 和授权机制，不新增账号池、登录器或自动续期器。

## 本地体验

Node 22，使用项目原有依赖，运行 `node scripts/operations/preview.js`。

- `http://127.0.0.1:4601/`：完整管理界面合成预览。
- `http://127.0.0.1:4610/`：另一个 HTTP 服务提供的合成状态页。
- 所有账号、扫码、任务和报告均为合成数据；不会打开 IMA、读取真实账号配置或发出 IMA 请求。合成页面有明确提示。
- 现有生产后台不被替换；`/admin-legacy.html` 保留旧版兼容入口。
- 新状态服务严格绑定 loopback。暂不新增公网或 Tailscale 路由。

## 数字和状态的定义

1. 登记数不是可服务账号数；旧资格不是有效登录证明。
2. 同时回答上限不是在线访客人数，暂不推算可在线人数。
3. 忙碌账号仍可服务，空闲名额另算；有名额不等于已验证稳定并发。
4. `operator_trial` 表示试运行，`validated` 表示已有匹配证明，`default` 表示默认限制。没有匹配依据就显示待核对。
5. 模式、身份和资格仍由既有调度模块决定。概览不会为展示改写账号、放开隔离或修改 Air 策略。
6. 部分账号失效但仍有可用容量时显示部分降级，不显示整站不可用。
7. 没有真实完成样本，不填 100% 成功率或虚构延迟。被动指标仅含本进程已进入派发、且观察到完成或失败的最近一小时最多 512 条样本；不包含入口拒绝或尚未派发的队列取消。重启后重新采集。

## 刷新与独立进程

后台每 5 秒只读刷新，无并行重叠请求，后台标签暂停，失败指数退避（最长 60 秒）。运行快照超过 15 秒失效。筛选、焦点、已展开菜单、抽屉和演练草稿不因自动刷新重建。

`GET /api/admin/overview` 保持管理员认证，只读已驻留数据；不读取私有账号文件、不续期、不扫码、不运行资格问答。初次载入及手动刷新仍读取既有 bootstrap 和账号详情；这也不会发起上游业务操作。

独立状态进程不加载 Provider 启动代码、profile 或账号存储。Provider 重启/失联后，状态服务仍可响应并把过期数据标为未知。同一台机器整体断网或关机不能靠本机状态页证明在线。

### 复用现有宿主监控

`health-monitor.patch` 是尚未应用的宿主补丁，可选启用同一独立监控进程中的状态 HTTP 服务：

- `PROVIDER_STATUS_UI=1` 开启，默认不启动。
- `PROVIDER_SOURCE_ROOT` 指向本次审核后的 Provider 代码目录。
- `PROVIDER_STATUS_PORT` 默认 4610。
- 历史写入既有私有监控目录下 `history/`，目录 0700、文件 0600。
- 复用原监控每 30 秒写入的 `health.json`，读取网站/认证及明确的 `tailnet.ready`；缺少私网检查数据时显示未知。不能用本机 relay 的 HTTP 200 冒充私网验证。
- 网络检查超过 90 秒过期。不会通过此补丁增加真实问答、扫码或续期检查。

也可独立启动 `scripts/operations/status-server.js`，显式设置私有绝对目录 `PROVIDER_STATUS_DIRECTORY`；`PROVIDER_HOST_HEALTH_PATH` 可指定现有宿主检查快照。未指定时只检查本机网站健康，私网保持未知。

私网访问需在部署窗口使用既有受控入口，仅转发状态页的只读静态文件与 `/api/status`。不得向私网开放 `/api/admin/*`，不得把管理员凭证放入浏览器。当前代码严格检查 loopback Host 和对端地址，因此不能直接把监听地址改为 `0.0.0.0` 当作完成私网部署。

## 30 天历史、磁盘与性能

- 按分钟异步追加 JSONL，只存白名单状态与汇总；状态改变另记 transition。
- 滚动保留 30 天、容量最多 32 MiB；按天文件淘汰，容量紧张可减少历史覆盖，并明确展示实际覆盖。
- 未采集、缺口、旧日期为灰色；同一分钟的重复记录（例如进程重启）不会重复计算覆盖。
- 历史与账号/会话/任务日志完全独立，无回答主线程同步刷盘。监控磁盘失败单独显示，不拖累问答。
- 本地 30 轮对照和更长合成趋势结果见 `validation.json`。合成不替代生产长稳或设备真机验收。

## 故障含义

资格执行先取得证据，再可靠提交证明，最后同步调度。新的报告可附 `failureStage`：上游、资格提交、同步、报告保存。原报告原样保留，没有阶段的旧报告不猜补。

- `local_persistence_failed`：本地资格保存失败，不能据此判账号登录失效。
- `local_generation_conflict`：账号状态已变化，旧资格不能覆盖新凭证。
- `commitApplied=true` 加 `pool_sync_failed`：资格已保存，调度同步失败，不能说“没有保存”。
- 未知或中断继续沿用既有保护与任务标识，不自动再问一次。
