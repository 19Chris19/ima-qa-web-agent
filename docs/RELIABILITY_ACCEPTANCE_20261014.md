# Provider 可靠性候选验收（2026-10-14）

基线为 Provider v0.6.0（main c329104e376be5d385814f790e5b17eab082fdb1）。常驻 worker 串行提交账号事务，HTTP 只读已确认缓存；使用统计每秒合并，空闲维护不提交整库。关键状态仍使用 CAS、摘要、生命周期 fence、原子替换和文件/目录刷盘，保护期 20 秒，队列最多 64 个等待操作。不会把本地存储故障当成 IMA 登录失效。

Node 22.23.3 全量回归 926 通过、6 个既有跳过、0 失败；随后追加的 managed 自动刷新及旧回调隔离专项通过，共 927 个有效测试。覆盖慢写、磁盘失败、锁冲突、提交回执丢失、worker 在 rename 后退出、兼容导出失败、文件损坏/丢失、缺少原密钥、统计字段白名单、旧凭证拒绝覆盖、资格绑定及正常/非正常退出后的统计回退。Docker COPY 布局启动同样经过合成验收；未启动真实账号池。

慢写达到保护期限时，故意不确认提交，停止新派发；已有测试流和健康 HTTP 可响应。每轮两次合成关键写入是用于对照的固定工作量，不是实际账号刷新频率。RSS 是 Node 进程整体（含线程）；旧子进程 CPU/RSS 未计入，所以不能直接相减推断总 CPU 收益。OS fsWrite 数值不是物理 SSD 写入量。真实 IMA 耗时、满载 3DGS 竞争、正式更新后的调度及长期运行仍未验收。

新增只读健康元数据 `persistence` 与认证管理员修复入口，见 [账号持久化说明](ACCOUNT_PERSISTENCE.md)。默认问答、SSE、历史和机器人合同保持兼容，现有 JSONL v2 不变；统计快照不能覆盖凭证、启停、资格或容量字段。配套网站修改见 [知天下 PR #18](https://github.com/19Chris19/explorer-ai-qa-demo/pull/18)。

本候选没有改变正在运行的服务、五账号登录态、密钥、Cookie 签名、会话历史、Vercel 或 Air 机器人。生产更新需另行授权，先关闭入口、证明排空、备份最新一致数据及私有兼容覆盖层，应用兼容后端再更新 BFF/工具/调度配置；真实扫码和问答验收另行确认。回滚先刷新并合并统计，保留最新历史与 JSONL v2，禁止恢复旧数据覆盖新记录。
