## Installation
Select the published v0.5.0 tag or complete source archive (including lockfile),
read README and docs/AGENT_DEPLOYMENT.md, and verify the attached release manifest
before using the ARM64/AMD64 image. Node and Docker are two paths for this same
version. Docker does not eliminate human scanning, phone confirmation or joining
the target knowledge base. Do not deploy floating main or an image without its
accepted manifest. A source document alone is not proof of publication.

## Evidence and boundaries
Full synthetic tests, packaging and native image startup are publication gates;
final results and immutable digests are attached to GitHub Release. Earlier Air
real long-question/follow-up evidence is dated and not a fresh acceptance of this
image. This publication sends no new real IMA questions. Windows desktop, remote
SSH enrollment, new-account end-to-end login/QA and real Linux long uptime remain
unverified. Air still has intermittent readiness failures under host pressure;
stable version selection does not certify Air availability or guarantee IMA's
undocumented web protocol will never change.

## Upgrade and rollback
Stop admission, drain active/queued work, back up private configuration and
current data, verify robot/custom extension compatibility and switch one writer
to the fixed source/image. Retain accounts, encryption keys, histories and task
logs. Publication alone does not restart Air, Docker Provider or robots.

Rollback only to compatible task-aware code after draining. Never overwrite new
data with an old snapshot, run two writers on one account store, or automatically
re-submit dispatched uncertain tasks. Authorize one real first question and
follow-up separately; verify upstream success, sources, exact text and history.
