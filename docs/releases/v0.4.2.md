# Provider A v0.4.2

Status: release preparation. Publish only after the reviewed main commit,
version tag, multi-platform images and installation checks agree. This document
does not itself declare the release available.

## What is included

One generic Provider service for Node or Docker: guided setup, desktop-maintained
enrollment, knowledge-base authorization, one bounded basic QA admission proof,
observable maintenance, isolated migration tooling and the generic QA UI.
The branded Explorer website remains a separate client and repository.

Use the versioned Git source (or GitHub source archive) with package-lock.json.
The npm packaging check is not a promise that its tarball is a standalone Docker
or onboarding distribution. Versioned Docker images support ARM64 and AMD64;
use the accepted release manifest to pin the image digest.

## New installation

Follow README and docs/AGENT_DEPLOYMENT.md from this exact tag. The recommended
onboard.sh/onboard.ps1 path checks prerequisites, resolves the supplied official
IMA share link and prepares a dedicated deployment. Existing installations and
orphan project volumes must not be reinitialized or silently adopted.

The human performs QR scanning, phone confirmation and knowledge-base joining.
A running service or valid login is not proof of knowledge QA. The explicit
enrollment flow describes its one-question validation; normal state checks do
not send questions. Generic IMA web-search capability remains unknown without
independent evidence and does not block proven knowledge QA.

## Upgrade

1. Review this version's enrollment, migration and maintenance contracts against
   custom extensions. This release does not automatically update running Air
   services or the WeChat bot.
2. Record the running source/image and deployment configuration. Back up private
   state and encryption keys securely without printing or committing them.
3. Test a separate installation first. Arrange an idle maintenance window, stop
   new submissions and drain queues before replacing the service image/code.
4. Do not rerun initialization or share an account volume between instances.
   Pending transfer bundles made without the durable QA guard must be prepared
   again from reviewed, stopped snapshots; never edit them to bypass validation.
5. Verify health, credential separation, account readiness and existing history.
   With explicit authorization, perform a real first question and follow-up to
   check streaming, sources, completion and session continuity.

## Rollback

Stop the candidate before selecting the previous reviewed image/code. Keep the
current account and conversation data; do not overwrite newly created records
with an older backup. Account migration rollback is a separate guarded procedure
in docs/SOURCE_RETIREMENT.md and docs/ACCOUNT_TRANSFER.md. Keep the source retired
until that procedure proves it is safe to reactivate; missing target records are
not proof of successful rollback.

## Acceptance boundary

Synthetic tests and disconnected container checks cannot prove real IMA access.
Final published artifact evidence belongs in the Release manifest and acceptance
record. Native Windows, maintenance-to-Linux SSH, new-account scan and follow-up,
token renewal longevity and long-running Linux production operation remain
unverified unless explicitly reported for the exact artifact. Air's existing
accounts and successful running service are not substitutes for those checks.
