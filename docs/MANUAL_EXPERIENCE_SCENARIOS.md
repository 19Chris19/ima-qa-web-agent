# 人工体验场景

这份清单用于人工对照 IMA 网页版 `@共享知识库` 和本项目 `ima-web-agent`。每个场景先问首问，等回答完成后再问追问；不要把多个场景混在同一个会话里。

## 场景一：基础问题是否直接

首问：

> 什么是 3D 高斯泼溅（3DGS）？它和 NeRF 等传统方法的核心区别是什么？

观察：

- 是否先给定义，再讲区别，而不是先说“资料不足”。
- 是否能引用多份不同资料，而不是只有一条来源。
- 引用序号是否能在来源卡片中找到对应标题。

## 场景二：参数问题是否积极调度

首问：

> 使用无人机进行航拍采集时，如何规划飞行路径和重叠率以获得最佳效果？请同时说明航向重叠、旁向重叠、视角多样性和照片数量之间的关系。

追问：

> 如果重叠率已经很高，但模型仍然出现空洞、重影或局部模糊，下一步应该排查什么？

观察：

- 是否同时调动 `80/70`、`75-85`、`60` 下限、视角多样性、照片数量和显存约束等不同证据。
- 追问是否承接上一轮，而不是重新解释“什么是 3DGS”。
- 是否能区分“重叠率过高”和“视角单一”这两个问题。

## 场景三：故障排查是否给出动作

首问：

> 训练过程中遇到 Loss 发散或 NaN，应该按什么顺序排查？请区分采集数据、空三、参数和硬件显存四类原因。

追问：

> 如果降低分辨率后仍然 NaN，但空三看起来正常，下一步优先检查哪些参数或训练现象？

观察：

- 是否按“现象 -> 原因 -> 操作 -> 验证结果”的顺序组织。
- 是否给出知识库里出现过的失败边界，而不是泛泛建议“检查配置”。
- 追问是否保留故障上下文。

## 场景四：工具对比是否有取舍

首问：

> PostShot、BSD、LichtFeld Studio、RealityScan 在训练速度、显存占用、稳定性和最终效果上有哪些差异？请按使用场景给出选择建议。

追问：

> 如果我的素材量大、显存有限，但更在意稳定交付，应该优先牺牲哪一项效果，选择哪类工作流？

观察：

- 是否按比较维度组织，不把几款软件混成一段。
- 是否把群聊里的经验和明确事实区分开。
- 是否承认证据不足的维度，而不是编造版本、价格或官方性能数据。

## 场景五：大场景综合方案

首问：

> 针对整个园区或城市街区这类巨型场景，如何安排无人机采集、地面补拍、分块训练、LOD 和在线流式加载？请给出从采集到交付的顺序。

观察：

- 是否能调动不同日期、不同群聊的资料，形成完整流程。
- 是否覆盖空地融合、分块边界、显存和在线端性能。
- 是否给出可以执行的先后顺序，而不是只列关键词。

## 场景六：边界与新会话

先在当前会话问：

> 训练好的 3DGS 模型如何转换成 Mesh 或用于 3D 打印？

然后点击“新建会话”，再问：

> 使用手机拍摄的素材能否用于 3DGS 训练？主要局限是什么？

观察：

- 新会话是否不带入上一会话的 Mesh/打印上下文。
- 刷新页面后当前会话是否仍能恢复。
- 切换回旧会话后，旧问题、回答和来源卡片是否仍在。

## 记录方式

每个场景只记录五项：

```text
场景：
首字速度：快 / 一般 / 慢
回答积极性：0-2
追问衔接：0-2
引用可靠性：0-2
主要问题：
```

判断优先级：先看回答是否真正解决问题，再看来源数量；来源多但答案空泛，不算通过。人工体验期间不要同时开两个问题，两个、五个或十个并发交给 `scripts/test-concurrency.mjs`。
